# 초기 실행 모델 0.1

## 목적과 현재 범위

학생이 실행 가능한 교통공학 기준 모델이다. 세 개의 가상 교차로를 실제 SUMO에서 실행하고, 관측한 교통 상태에 따라 중앙 교차로의 녹색 배분을 추천한다. 규칙 기반 진단과 반복 시뮬레이션이 작동하는 단계이며 학습된 AI 모델은 포함하지 않는다. 실제 둔대교차로의 혼잡이나 개선 효과를 검증한 결과는 아니다.

| 설계서 항목 | 초기 구현 | 남은 검증·확장 |
| --- | --- | --- |
| 상태 입력 | SUMO의 완전한 차량 상태와 과거 출발 요청 관측 | 실제 검지기·영상의 오차, 결측과 가림 반영 |
| 원인 후보 | 유입 증가·녹색 배분 불균형·하류 막힘의 설명 가능한 규칙 | 사건 대조 실험에 의한 원인 라벨과 학습·외부 검증 |
| 대안 생성 | 기준 벡터에 대한 ±5초 이동 8개와 변경 없음 | 실제 회전 연결·보행·기관 운영 제약 |
| 대안 비교 | 과거 유입률로 생성한 9개 수요 표본, 2주기 기본 지평 | 실제 예측 오차·다른 망에서의 일반화 |
| 비교 정책 | 고정, 진단 필터 없는 탐색, 제안, 전체 후보 탐색 | 조정된 감응신호 기준 및 상용 도구 비교 |
| 실증 | 합성 실행·스냅샷·비누출 테스트 | 실측 보정·그림자 운영·승인된 현장 비교 |

## 필요한 데이터셋

외부 데이터셋 없이 실행한다. 첫 추천기는 지도학습을 하지 않는다. 다음 세 입력을 코드가 자동 생성한다.

1. **도로망:** A·B·C 교차로, 중심 간 거리 300m, 방향별 1차로, 직진 연결과 경로 8개.
2. **신호 계획:** W·N·E·S 순서의 독립 보호현시. 녹색 30·20·30·20초, 각 현시 뒤 황색 3초·전적색 2초. 총 120초. A/C 옵셋은 모두 0으로 고정한다.
3. **차량 출발 요청:** 경로별 포아송 도착을 정수 초로 양자화한다. 난수 시드와 수요 조건으로 재생성하며 차량 추종의 `sigma`와 `speedDev`는 0이다.

`realized_demand.json`의 한 행은 다음 형태이다.

```json
{"time": 12, "route_id": "eastbound", "vehicle_id": "real_eastbound_0"}
```

`time`은 출발을 요청한 시뮬레이션 초이다. 실제 도로 진입 시각과 다를 수 있다. 진입이 밀리면 원래 요청 시각을 유지한 채 미삽입 원장에 남긴다. JSON은 평가자의 실현 수요이며 추천기에 전달하지 않는다.

| 수요 조건 | 생성 방법과 해석 |
| --- | --- |
| `normal` | 양방향 본선 280대/시, 각 교차 접근 경로 180대/시의 도착률 |
| `imbalanced` | 동행 520·서행 180대/시, B의 남북 경로 각 95대/시 |
| `surge` | 편중 조건의 전반부를 0.55배로 생성한 뒤 후반부 증가 |
| `downstream` | 동행 570·서행 240대/시, C의 남북 경로 각 430대/시 |

이 값은 관측 교통량이 아닌 가상 도착률이다. 각 실행의 실제 요청 수는 난수에 따라 달라진다. `downstream`도 물리적 차로 폐쇄나 병목 원인이 확정된 상황이 아니라 C의 교차 수요를 높인 스트레스 조건이다. 시나리오 이름은 추천기에 전달하지 않는다.

실제 장소로 보정할 때는 차로·회전 연결, 실행 신호 로그와 공통 시각, 방향별 교통량·대기행렬·하류 저장공간이 필요하다. 영상은 계측 모듈의 입력과 수작업 정답 검수에 사용한다. 학습형 진단기를 만들 때는 서로 독립인 상황 단위로 학습·검증·시험을 나누고, 주입한 사건과 실제 병목 영향을 구분해야 한다. 현재 생성 기록만으로 실제 원인의 정답 라벨이 확보된 것은 아니다.

## 실행 흐름과 정보 분리

1. 평가자만 전체 실현 출발 요청을 보유한다. 각 SUMO 프로세스에는 요청 시각이 도래한 차량만 TraCI로 추가한다. SUMO 경로 정의 파일에는 미래 차량·flow를 넣지 않는다.
2. 480초까지 준비 실행한다. 최근 4개 완료 주기와 10초 간격 관측은 유지하되 평가 J와 통행 집계의 원점은 480초로 바꾼다.
3. 첫 판단 자료를 580초에 마감하고 600초 적용을 검토한다. 이후 700→720초, 820→840초처럼 반복한다. B의 신호 프로그램 변경은 120초 주기 경계에서만 허용한다.
4. 최근 3개 완료 주기의 경로별 **외부 출발 요청** 관측률을 사용한다. 진입하지 못한 요청도 완전히 관측한다는 가정이므로 실제 노변 통과량과 동일하지 않다.
5. 관측률에 0.8·1.0·1.2배를 적용하고 각각 3개 계획 도착열을 만든다. 이 배율은 확률·신뢰구간이 아니다. 계획 난수는 실현 수요 시드와 분리한다. 후보 간에는 같은 계획 표본을 쓴다.
6. 같은 상태에서 후보별로 분기한다. 적용 시각 전까지 기존 신호를 유지하고, 첫 적용 주기는 후보, 다음 주기는 기준으로 평가한다. `--horizon-cycles 4` 또는 `8`에서는 첫 주기 이후 기준을 유지한 채 지평을 늘린다.
7. 추천이 확정되면 평가자의 해당 정책 프로세스에서만 적용한다. 각 정책은 자신의 상태로 계속 진화한다. 다음 판단 때 기준 정책의 상태로 되돌리지 않는다. 다음 추천이 있으면 앞서 예정했던 기준 복귀를 새 후보로 바꿀 수 있다.

`evaluate_cutoff()`의 입력에는 실현 미래 수요·시나리오·실현 시드가 없다. 스냅샷은 현재 존재 차량의 전체 상태와 알려진 경로를 사용한다. 따라서 영상만으로 이 상태를 복원할 수 있다는 주장은 하지 않는다.

## 원인 후보와 추천

진단은 원인 확정이 아니다. 다음 가상 초기 규칙을 사용한다.

- 최근 완료 주기의 유입이 앞선 3주기 평균의 1.2배를 넘고 행렬이 증가하면 유입 증가 후보.
- 두 주기 연속 녹색 종료 후 잔류가 있고 하류 저장공간 사용률이 0.6 미만이면 배분 불균형 후보.
- 기동 구간 후 수요가 있는 녹색에서 10초 연속 배출이 없고 잔류 및 하류 사용률 0.8 이상이 동반되면 하류 막힘 후보.
- 필수 상태·완료 주기 이력·자료 품질이 부족하면 미상과 추천 보류. 버스·보행 진단은 비활성화.

하류 사용률은 차량 수 / 가상 저장 대수이며 검지기의 시간 점유율이 아니다. 저장 대수는 차로 길이 / 차량 길이와 최소 간격 합 7.5m를 내림해 정한다. 녹색 최소 15초·최대 45초도 실험 제약이지 현장 안전 기준이 아니다.

현시쌍 (1,2), (2,3), (3,4), (4,1) 사이에서 5초를 양방향 이동해 최대 9개 후보를 만든다. 매번 승인된 기준 30·20·30·20초에서 생성하며 변경을 누적하지 않는다. 잔류/저장용량 비율의 수혜 방향과 회수 방향 차이로 순위를 정하고, 하류 막힘 방향의 녹색 증가를 제외한다. 변경 없음과 상위 4개를 평가한다. `no_diagnosis`는 같은 예산과 잔류 순위에서 해당 진단 필터만 제거한다.

후보 채택은 다음 조건을 모두 충족해야 한다.

| 가상 채택 조건 | 구현 |
| --- | --- |
| 자료 | 신호·상태가 유효하고 최근 특징 유효 비율 90% 이상, 완료 주기 4개 이상 |
| 평균 효과 | 9개 표본의 평균 기준 대비 상대 J 개선율 1% 이상 |
| 표본 악화 | 각 표본의 J 악화 2% 이하 |
| 전체 잔여량 | 종료 활성 차량이 기준+2대 이하, 미삽입 수요는 증가하지 않을 것 |
| B 방향별 행렬 | 종료 행렬이 max(기준×1.1, 기준+2대) 이하 |
| 이상·마감 | 충돌·텔레포트가 없고 계산 예산 내 완료 |

통과한 후보는 최악 J 변화율, 평균 변화율, 후보 ID 순으로 선택한다. 기준 J가 0이면 상대 개선을 계산하지 않는다. 개선 조건 미달이면 `keep`, 자료 불충분·기준 실행 이상·계산 지연이면 `abstain`이며 모두 기준 벡터를 반환한다. 계산 예산은 후보 실행 시작부터 결과 집계까지의 실측 벽시계 시간이다. 실행 도중 예산 초과를 확인하면 남은 가지를 중단하며 이미 실행 중인 1개 SUMO 가지가 끝나는 시간까지 지연될 수 있다.

## 지표와 산출물

J는 매 1초 실행 후 **망 안 활성 차량 + 예정시각을 지난 미삽입 차량**을 합한 우측 직사각 적분이다. 단위는 차량초이며 아직 목적지에 도착하지 않은 차량도 포함한다. 자유류 대비 지체만을 측정하는 지표는 아니다. 차량 삭제나 텔레포트로 지표를 좋게 만들지 않도록 텔레포트는 비활성화하고 발생 횟수도 검사한다.

| 필드 | 의미 |
| --- | --- |
| `objective_j` | 평가 원점(기본 480초) 이후 누적 차량초 |
| `terminal_vehicles` | 종료 시 망 안 활성 차량 수 |
| `terminal_uninserted` | 종료 시 출발을 요청했으나 진입하지 못한 수 |
| `terminal_queues` | 종료 시 B의 W·N·E·S 정차 차량 수 |
| `arrived`, `departed` | 평가 원점 이후 도착·진입 수. 준비 구간부터 존재하던 차량 때문에 도착 수가 진입 수보다 클 수 있음 |
| `scheduled` | 0초부터 종료까지의 누적 요청 수. 위의 구간 통계와 혼합해 완료율을 계산하지 않음 |
| `teleports`, `collisions` | 평가 원점 이후 발생 수 |

`history.csv`는 준비 구간을 포함한 전체 10초 관측이다. `decisions.json`에는 당시 관측, 예측 표본의 해시, 후보별 지표와 탈락 이유, 계산시간이 있다. `summary.json`에는 가정·수요 해시·소스 해시·신호 제약·SUMO 버전을 기록한다. 생성된 XML은 실행 경로를 포함할 수 있어 `runs/` 전체는 커밋하지 않는다.

`benchmark.json`은 같은 시드의 정책 J 차이를 짝지어 평균과 Student-t 근사 95% 구간으로 요약한다. 독립 표본 단위는 차량이 아닌 수요 시드 실행이다. 반복 수가 작으면 탐색적 결과이며, 신뢰구간이나 합성 실험으로 현장 효과를 보장하지 않는다. 기본 2주기 지평과 종료 제약도 이후 부담 전가를 완전히 배제하지 못하므로 4·8주기 민감도 검토를 별도로 실행할 수 있다.

## 상태 복원의 검증

SUMO의 마지막 스텝 통계는 상태 로드 직후 채워지지 않으므로 관측 캐시도 저장한다. 미진입 요청은 원래 예정시각·경로·ID를 가진 별도 원장에 보존한다. SUMO 1.28의 TraCI 미진입 차량은 상태 XML에 차량 레코드를 남기지만 삽입 대기열이 그대로 복원되지 않는 동작을 실제 테스트에서 확인했다. 중복·가상 충돌을 방지하기 위해 미진입 레코드를 XML에서 제외하고, 프로세스 내부를 초기화해 활성 상태를 복원한 뒤 원장으로 다시 추가한다.

실제 SUMO 테스트는 미진입 96대를 포함한 상태의 연속 실행과 최초·반복 복원의 지표 일치, 비영 행렬의 즉시 복원, 전혀 다른 미래 수요의 비누출, B 변경 중 A/C의 매초 신호 일치를 확인한다. 전체 테스트 실행 명령은 다음과 같다.

```bash
python -m unittest discover -s tests -v
```
